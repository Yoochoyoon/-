## 개요

`01`~`08` 기획 문서를 바탕으로 실제 플레이 가능한 웹앱 MVP를 만들었다. 이 문서는 기획 문서에는 없는, 이번 개발 세션에서 정해지거나 알아둬야 할 것들만 정리한다(설치·실행법은 `README.md` 참고, 게임 규칙 자체는 `01`~`08` 참고).

## 기술 스택 & 실제 구현 범위

- **스택**: Node.js + TypeScript + Express + Socket.IO 백엔드, 빌드 도구 없는 순수 HTML/CSS/JS 프론트(React 사용 안 함), Render.com 배포 예정.
- **상태 저장**: 메모리에만 저장 — DB 없음. 서버가 재시작되면 진행 중이던 모든 방이 초기화된다(MVP 한정 허용).
- **이번에 구현된 것**: 8명 고정 입장, 역할 자동배정, 밤(기본 공격만 — 특수 능력 없음) 데미지 합산, 낮(결과공개 → 토론 → 투표), 동점 시 재투표, 승리조건 판정, 진행자의 타이머 강제진행·연장.
- **아직 구현 안 된 것** (기획 문서엔 있지만 코드엔 없음): 인원수 6~10명 가변, 7개 역할별 특수 능력(육탄방어·충성심서약·암둠의공모·교란작전·긴급처형·이중스파이·흑막의미소) 전부, 1라운드 탐색 라운드 구분, 사망자 관전 UI, 재접속 자동 복귀, 첫판 힌트 툴팁, 닉네임 중복 방지.

## 코드 짜면서 새로 정한 것들 (기획 문서엔 없던 세부사항)

- **진행자(host)는 8명 역할에 포함되지 않는 별도 컨트롤러**로 구현했다. `06컴포넌트테크구현.md`에는 "진행자도 역할을 겸해 참가할 수 있다"고 돼 있지만, MVP에서는 진행자=관전+컨트롤 전용이고 겸직은 2차 작업으로 미뤘다.
- **TV 화면은 자동 연결이 아니라 방 코드를 직접 입력**해서 연결한다(추후 QR코드 등으로 개선 가능).
- **자기 자신은 밤 지목/낮 투표 대상에서 제외**된다(자기공격·자기투표 불가) — 문서에 명시되지 않아 상식적으로 정한 부분.
- **결과 공개(낮 데미지 공개) 페이즈는 타이머가 없다** — 진행자가 화면에서 "토론 시작하기" 버튼을 눌러야 다음(토론)으로 넘어간다.
- **방 코드는 헷갈리는 문자(0/O, 1/I)를 제외한 4자리**로 자동 생성된다.
